# Community-reported hub revisions

<Callout type="warning">

**Not maintainer-verified.** The [manual update](/core/firmware-updates/manual-update/) covers `F03` and `F04` hubs. The revisions on this page come from community reports on a single unit each. Read the report, keep your [backups](/core/firmware-updates/manual-update/#step-1-back-up-the-existing-pod-state), and verify the result on your own hardware.

</Callout>

`frankenfirmware` reads the hub label from `/deviceinfo/device-label` at boot and looks for a block with the same revision in `/opt/eight/config/machine.json`. If no block matches, it falls back to the default NXP i.MX 8M Mini ports (`/dev/ttymxc0`). The cover and hub controller then stay disconnected, and temperature commands fail with `[thermostat] %s heat-on rejected - no peripheral connected`.

## Find your revision

```bash
ssh -p 8822 root@POD_IP "cat /deviceinfo/device-label"
# Example: 20500-0003-F08-...
```

The revision is the third dash-separated field (`F08` above). If it is `F03` or `F04`, follow the manual update without changes.

## Add a block for your revision

In the [Step 6](/core/firmware-updates/manual-update/#step-6-configure-uart-mapping-metadata-stubs-and-stage-cover-firmware-pod-3-hub--pod-4-cover) `machine.json`, add a block named after your revision next to `F03` and `F04`. Keep the root-level keys, because `capybara.service` reads only those:

```json
"F08": {
  "sensorPort": "/dev/ttyS2",
  "frozenPort": "/dev/ttyS1"
}
```

In the Step 6 `ssh` command, the JSON sits inside a double-quoted string, so escape each quote as `\"`, matching the existing blocks.

## Confirm the mapping

After restarting `frank.service`, confirm that the daemon picked your block and the expected ports:

```bash
ssh -p 8822 root@POD_IP "journalctl -u frank -b --no-pager | grep -E 'Using machine config|sensor path'"
# Expected:
# INF: DeviceInfo.cpp getPorts | Using machine config for hwRev F08 (device hwRev: F08)
# INF: main.cpp | sensor path: /dev/ttyS2 frozen path: /dev/ttyS1
```

If the log still shows `/dev/ttymxc0`, the block name does not match the label. Check spelling and case.
